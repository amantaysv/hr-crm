# ТЗ на дизайн — «Кызмат · Вакансии» (HR CRM)

## 1. Что это за продукт

Небольшой карьерный сайт + мини-ATS для одной организации (Кыргызстан, интерфейс на русском).

Две части:

- **Публичная** (без авторизации): соискатель смотрит список открытых вакансий, открывает карточку и отправляет отклик с резюме.
- **Админка** (вход по email/паролю): HR создаёт и редактирует вакансии, смотрит отклики по каждой вакансии, фильтрует их и меняет статус кандидата (мини-воронка найма).

Масштаб реальный и маленький: единицы вакансий, десятки-сотни откликов. Один админ (ролей нет). Уведомления на почту при новом отклике (код готов, включается ключом).

**Тон:** государственно-корпоративный, но современный и лёгкий. Не «стартап-лендинг» с градиентами, но и не серый портал. Приоритет — читаемость, доверие, скорость заполнения формы с телефона.

## 2. Технические рамки (важно для дизайна)

Дизайн должен быть реализуем на текущем стеке без замены библиотек:

- **Next.js 16 (App Router) + React 19**, серверные компоненты, серверные экшены.
- **Tailwind CSS v4** + **shadcn/ui поверх Base UI** (`@base-ui/react`). Уже используются компоненты: Button, Input, Textarea, Label, Select, Card, Alert, Badge.
- **Иконки:** `lucide-react` (сейчас: Briefcase, Users, Pencil, Plus, Wallet, Search, Mail, Phone, CalendarDays, FileText, Link2, Inbox, ArrowRight, ArrowLeft, Sun, Moon, LogOut).
- **Шрифты:** Geist Sans / Geist Mono (next/font).
- **Токены:** CSS-переменные в `oklch` — `--background`, `--foreground`, `--card`, `--primary`, `--muted`, `--muted-foreground`, `--border`, `--input`, `--ring`, `--destructive`, `--radius: 0.625rem`. Палитра сейчас **полностью нейтральная (zinc/neutral, ахроматичная)**, единственный цветной акцент — `emerald` для зарплаты и точки статуса «Открыта».
- **Тёмная тема обязательна:** по системной настройке + ручной переключатель (атрибут `data-theme` на `<html>`, значение в localStorage). Любое цветовое решение должно работать в обеих темах.
- **Markdown** в описании вакансии рендерится через `@tailwindcss/typography` (`prose`).
- Ширины контейнеров сейчас: публичные страницы `max-w-3xl` (список) / `max-w-2xl` (карточка вакансии), админка `max-w-5xl`, логин `max-w-sm`.

**Чего не делать:** не предлагать новые UI-библиотеки, не завязываться на анимационные фреймворки, не требовать иллюстраций/фото (их нет и не будет), не проектировать функционал вне списка ниже.

## 3. Модель данных (что реально есть)

**Вакансия (`vacancies`)**

| Поле | Тип | Комментарий |
|---|---|---|
| `title` | текст | обязательное |
| `description` | Markdown-текст | может быть пустым |
| `salary` | свободный текст | напр. «150 000 - 200 000 сом», может быть пустым |
| `status` | `open` / `closed` | «Открыта» / «Закрыта» |
| `created_at` | дата | вакансия моложе 3 дней помечается бейджем «Новая» |

Полей «локация», «тип занятости», «требования» **нет** — их удалили осознанно. Не возвращать их в дизайн.

**Кандидат / отклик (`candidates`)**

| Поле | Тип | Комментарий |
|---|---|---|
| `name` | текст | «Имя Фамилия», обязательное |
| `email` | email | обязательное |
| `phone` | телефон | подпись «Телефон (WhatsApp)», обязательное |
| `expected_salary` | число | «Ожидаемая ЗП (на руки)», необязательное |
| `start_date_option` | `asap` / `1_week` / `2_weeks` / `other` | «Сразу» / «Через неделю» / «Через 2 недели» / «Другое» |
| `start_date_other` | текст | показывается только при выборе «Другое» |
| `citizenship` | текст | выбор «Кыргызстан» / «Другое» → поле для ввода |
| `education` | `higher` / `vocational` / `course_certificate` / `none` | «Высшее» / «Средне-специальное» / «Сертификат об окончании курсов» / «Нет» |
| `portfolio_url` | ссылка | «Ссылка на портфолио / LinkedIn», необязательное |
| `resume_path` | файл | PDF/DOC/DOCX, **обязательное**, лежит в приватном хранилище, админ качает по временной ссылке |
| `status` | воронка | `new` «Новый» → `screening` «На рассмотрении» → `interview` «Собеседование» → `offer` «Оффер» → `hired` «Нанят» / `rejected` «Отказ» |
| `created_at` | дата | в списке показывается относительно: «сегодня», «вчера», «5 дней назад», дальше — «12 марта» |

## 4. Экраны — что есть сейчас и что нужно от дизайна

Ниже — фактическое текущее состояние. Нужен редизайн каждого экрана: сетка, типографика, иерархия, состояния, мобильная версия.

### 4.1. Публичный шаблон
Хедер: слева текстовый логотип-ссылка «Кызмат - Вакансии», справа переключатель темы (иконка). Снизу футер: «© 2026 Кызмат - Вакансии» и e-mail для вопросов (может отсутствовать).
→ Нужно: аккуратный хедер/футер, возможно место под герб/лого организации.

### 4.2. Список вакансий (`/`) — главная
- Заголовок H1 «Найдите работу мечты», подзаголовок «Выберите вакансию, чтобы узнать подробности и оставить отклик.», счётчик «3 открытые вакансии» (склонение по-русски) или «Открытых вакансий пока нет».
- Поле поиска по названию (иконка лупы внутри слева), фильтрация мгновенная на клиенте.
- Карточки вакансий в один столбец: название, бейдж «Новая», зарплата с иконкой кошелька (изумрудный), два первых строки описания (обрезка), «Опубликовано 3 дня назад», стрелка вправо со сдвигом на ховере. Вся карточка — ссылка.
- Состояния: пусто (вакансий нет), «Ничего не найдено по запросу «…»».
→ Нужно: сильная посадочная зона наверху, читаемый ритм карточек, ховер/фокус состояния, вид на мобильном.

### 4.3. Карточка вакансии (`/vacancies/[id]`)
- Ссылка назад «Все вакансии».
- H1 с названием + бейдж «Новая», строка зарплаты с иконкой.
- Блок «Описание» — отрендеренный Markdown (заголовки, списки, ссылки, жирный/курсив, таблицы GFM).
- Разделитель, дальше блок «Откликнуться» — форма прямо на странице (не модалка).
→ Нужно: типографика Markdown-блока, визуальное отделение формы, возможен «липкий» блок отклика на десктопе.

### 4.4. Форма отклика (на карточке вакансии)
Поля по порядку: Имя Фамилия, Email, Телефон (WhatsApp), Ожидаемая ЗП (на руки), Дата выхода (select) → «Уточните дату выхода» при «Другое», Гражданство (select) → «Уточните гражданство» при «Другое», Образование (select), Ссылка на портфолио / LinkedIn, Резюме (файл, PDF/DOCX). Кнопка «Отправить отклик» / «Отправка...» (disabled).
Ошибки — единым алертом внизу («Прикрепите файл резюме», «Не удалось загрузить файл резюме», «Не удалось отправить отклик»).
Успех — вся форма заменяется на алерт «Спасибо! Ваш отклик отправлен.»
→ **Это ключевой экран продукта.** Нужно: 9 полей не должны пугать — сгруппировать, задать плотность, продумать нативный file-input (сейчас он выглядит некрасиво), состояние загрузки, состояние успеха (сейчас скучный алерт — нужен нормальный success-стейт), inline-валидация вместо одного алерта внизу, мобильная версия.

### 4.5. Вход в админку (`/admin/login`)
Узкая центрированная карточка: лого-ссылка, заголовок «Вход в админку», Email, Пароль, алерт «Неверный email или пароль», кнопка «Войти».
→ Нужно: аккуратная страница входа.

### 4.6. Шаблон админки
Хедер: слева иконка портфеля + «Кызмат - Вакансии · Админка», справа переключатель темы и кнопка «Выйти». Контент по центру, `max-w-5xl`.
→ Нужно: решить, оставлять ли верхнюю навигацию или вводить боковую (разделов пока один — «Вакансии», перегружать не надо).

### 4.7. Вакансии в админке (`/admin/vacancies`)
- H1 «Вакансии» + кнопка «Новая вакансия» (иконка +).
- Список карточек: название, точка статуса (изумрудная / серая) + «Открыта»/«Закрыта», справа кнопки «Кандидаты» и «Редактировать».
- Пусто: пунктирная рамка, иконка портфеля, «Вакансий пока нет.», кнопка «Создать первую».
→ Нужно: строки/карточки должны быстро сканироваться; **желательно показывать счётчик откликов у вакансии** (сейчас его нет — можно заложить в дизайн).

### 4.8. Создание / редактирование вакансии
Ссылка назад «К вакансиям», H1 «Новая вакансия» / «Редактировать вакансию».
Поля: Название; Описание с переключателем «Написать · Предпросмотр» (Markdown) и подсказкой «Поддерживается Markdown: **жирный**, *курсив*, списки, ссылки.»; Оклад (плейсхолдер «150 000 - 200 000 сом»); Статус (Открыта/Закрыта). Кнопка «Сохранить».
→ Нужно: нормальный редактор-таб «Написать/Предпросмотр» (сейчас две текстовые кнопки), возможно панель с Markdown-кнопками, sticky-кнопка сохранения.

### 4.9. Кандидаты по вакансии (`/admin/vacancies/[id]/candidates`) — самый насыщенный экран
Слева боковая колонка фильтров (`lg:w-64`, на мобильном — сверху):
- Поиск «Поиск по имени, телефону или email»
- Кнопка «Сбросить фильтры» (появляется, если фильтры активны)
- «Статус» — 6 бейджей-переключателей (мультивыбор)
- «Дата выхода» — 4 бейджа
- «Ожидаемая ЗП» — два числовых поля «От» – «До»
- «Образование» — 4 бейджа
- «Гражданство» — один бейдж «Кыргызстан»

Справа список карточек кандидатов: имя; строки email / телефон / «Откликнулся 2 дня назад» с иконками; справа сверху — компактный select статуса (сохраняется сразу при выборе); строка сводки «Ожидаемая ЗП (на руки): 120000 · Дата выхода: Сразу · Гражданство: Кыргызстан · Образование: Высшее»; ссылки «Резюме» и «Портфолио».
Отказанные кандидаты уезжают в конец списка.
Состояния: «По этой вакансии пока нет откликов.» и «Ничего не найдено по заданным условиям.» (пунктирная рамка + иконка).
→ Нужно: **главная задача редизайна.** Фильтры не должны шуметь, активные фильтры должны читаться с первого взгляда; карточка кандидата — плотная и сканируемая (сейчас сводка идёт сплошной строкой через «·» — просится сетка/чипы); статус должен быть цветокодирован (сейчас нейтральный select, «Нанят» и «Отказ» ничем не отличаются); отказанные — визуально приглушить. Мобильная версия: фильтры сворачиваются.

## 5. Что нужно на выходе

1. **Цветовая система**: набор токенов в `oklch` для светлой и тёмной темы. Можно уйти от полностью серой палитры к сдержанному фирменному акценту — но акцент один, и он должен нормально работать на кнопках, фокус-кольцах и бейджах в обеих темах.
2. **Цвета статусов кандидата** — 6 значений воронки, различимых и не кричащих; плюс статус вакансии (открыта/закрыта).
3. **Типографическая шкала** (H1/H2/подписи/подсказки) и правила для Markdown-блока.
4. **Компоненты**: кнопка (варианты default/outline/ghost/link, размеры sm/default/icon), поле ввода, select, textarea, чекбокс-бейдж-фильтр, карточка, бейдж, алерт, пустое состояние, загрузка файла, скелетоны/состояния загрузки.
5. **Макеты всех 8 экранов** из раздела 4 — десктоп и мобильный, светлая и тёмная тема.
6. **Все состояния**: пусто, загрузка, ошибка, успех, «ничего не найдено», отправка формы, disabled.

## 6. Ограничения и не-цели

- Весь интерфейс на русском (в перспективе возможен кыргызский — не закладывать узкие фиксированные ширины под текст).
- Мобильный трафик соискателей — приоритетный; админка в основном с десктопа.
- Ролей и прав нет, дашбордов/аналитики нет, чатов и календаря нет, канбан-доски нет (статус меняется селектом в списке). Не проектировать это.
- Резюме — приватные файлы, открываются по временной ссылке; предпросмотра резюме в интерфейсе нет.
- Доступность: контраст, видимый фокус, кликабельные зоны от 44px на мобильном.
